本章总结了使用 SnapCenter 执行的备份、还原和恢复、SAP 系统刷新和异步复制操作。



[[backup-operations]]
== 备份操作

备份操作的执行方式与 https://docs.netapp.com/us-en/netapp-solutions-sap/backup/hana-sc-generic-backup-operations.html["在SnapCenter中了解 SAP HANA 快照的备份操作"]中所述的相同。


NOTE: 如果未为存储单元配置一致性组，则 SnapCenter 将使用第一个 Snapshot 备份操作创建一致性组和子一致性组。然后将 HANA 数据存储分配给子一致性组。SnapCenter 快照备份列在子一致性组中。

image:hana-sc-bare-metal-asar2-image-008.png["width=601,height=205"]



[[restore-and-recovery]]
== 还原和恢复

还原和恢复操作的执行方式与所述相同 https://docs.netapp.com/us-en/netapp-solutions-sap/backup/hana-sc-generic-restore.html["使用SnapCenter恢复 SAP HANA 数据库"]。



[[asynchronous-storage-replication]]
== 异步存储复制

对于 HANA 数据卷，已配置异步存储复制。

image:hana-sc-bare-metal-asar2-image-009.png["宽度=601，高度=180"]

已使用 MirrorAndVault 策略配置复制。

image:hana-sc-bare-metal-asar2-image-010.png["width=601,height=206"]

该 MirrorAndVault 策略包含不同的 SnapMirror 标签和保留期。

image:hana-sc-bare-metal-asar2-image-011.png["width=601,height=235"]

在 SnapCenter 中，已配置一个策略来匹配 ONTAP MirrorAndVault 策略的 SnapMirror 标签 "daily"。

image:hana-sc-bare-metal-asar2-image-012.png["width=378,height=354"]

使用 ONTAP MirrorAndVault 策略时，SnapCenter 显示分隔的 Vault 和 Mirror 副本，即使快照备份在目标存储中仅可用一次。

image:hana-sc-bare-metal-asar2-image-013.png["宽度=601，高度=294"]

[[snapcenter-workflow]]
=== SnapCenter 工作流

操作详细信息和先决条件在 https://docs.netapp.com/us-en/netapp-solutions-sap/lifecycle/sc-copy-clone-hana-sys-refresh-with-sc.html#prerequisites-and-limitations["使用SnapCenter 更新SAP HANA系统"]中进行了描述。具体来说，必须先将目标系统添加到 SnapCenter，然后才能执行第一次刷新/克隆操作。

在克隆工作流程的第一步中，必须提供目标主机和目标 SID。

image:hana-sc-bare-metal-asar2-image-014.png["width=333,height=313"]

协议选择必须为"FCP"。

image:hana-sc-bare-metal-asar2-image-015.png["width=334,height=312"]

您可以选择添加 sc-system-refresh.sh 脚本来自动执行恢复操作。

image:hana-sc-bare-metal-asar2-image-016.png["width=352,height=331"]

下面的屏幕截图显示了克隆工作流的作业日志。
